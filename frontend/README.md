# Попутно — веб-интерфейс TravelApp

React + Vite, обычный CSS, без дополнительных UI-библиотек. Все данные приходят из
существующих Java-сервисов. Расчёт долей, долгов, доступов и напоминаний выполняет backend.
Демонстрационные поездки и фиктивный вход в приложение не встроены.

## Запуск

Нужна версия Node.js, поддерживаемая установленным Vite (проверено на Node 24).
Сначала запустите userservice, tripservice и expensesservice с PostgreSQL и общим JWT_SECRET.
Для Telegram нужны также botservice и, для напоминаний, notificationservice.

Из папки frontend:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

В PowerShell вместо cp можно использовать Copy-Item .env.example .env.local.
Откройте адрес, который напечатает Vite (обычно http://localhost:5173).

Настройки .env.local:

- USER_SERVICE_URL — http://localhost:8082
- TRIP_SERVICE_URL — http://localhost:8083
- EXPENSES_SERVICE_URL — http://localhost:8084
- VITE_TELEGRAM_BOT_USERNAME — необязательное имя вашего бота без @.
  Добавляет кнопку перехода в бота, включая start-ссылку для привязки.
  Без него команду /link можно скопировать вручную.

Адреса сервисов использует Vite proxy. Браузер обращается только к /api/users,
/api/trips и /api/expenses на текущем домене. Дополнительный CORS в Spring не нужен.
Никогда не добавляйте JWT_SECRET, BOT_SERVICE_SECRET, NOTIFICATION_SERVICE_SECRET
или TELEGRAM_BOT_TOKEN в переменные VITE_*: они доступны браузеру.

## Что доступно

- Регистрация, вход, выход; понятное завершение сессии при истечении JWT или ответе 401.
- Профиль: имя, часовой пояс с подсказками, валюта и бюджет.
- Светлая/тёмная тема, сохранение языка профиля (сам интерфейс пока русский),
  включение/отключение Telegram-напоминаний.
- Одноразовый код привязки Telegram с таймером и копированием команды, проверка
  подтверждённого подключения, отключение бота.
- Список поездок, поиск, фильтр «Я организатор», создание, изменение и удаление.
- Перелёты: добавление, редактирование, удаление, местные даты и время через
  календарь, отдельные часовые пояса отправления и прибытия.
- Участники: добавление по ID, роли OWNER/MEMBER/READ_ONLY, изменение прав,
  удаление; последний владелец защищён от случайного удаления/понижения.
- Общая и личная история расходов, детали долей и автора записи, фильтр валюты.
- Расходы: плательщик, валюта, необязательная дата, выбранные участники,
  равные или вручную заданные доли, удаление по правам backend.
- Общие и личные итоги: оплачено, доля, баланс и попарные долги отдельно по валютам.
- Меню аккаунта в шапке: настройки профиля и выход. Удаления аккаунта на сайте нет.
- Адаптивные страницы, мобильное меню, диалоги с клавиатурной навигацией,
  состояния загрузки, ошибок и пустых списков.

Имена участников загружаются через POST /users/directory: только ID и отображаемое имя, без приватных полей профиля. При вводе ID форма показывает имя и разрешает добавление только после проверки. Tripservice повторно проверяет существование пользователя перед записью.
Добавление участников выполняется по существующему ID пользователя, не по логину.
Валюта профиля не конвертирует деньги. Расходы считаются в каждой валюте отдельно.
Переводы в погашение долгов backend пока не фиксирует.

## Авторизация и Telegram

JWT хранится в sessionStorage только текущей вкладки, а не в постоянном localStorage.
После закрытия вкладки вход восстанавливается по HttpOnly cookie. Срок входа по умолчанию — 7 дней, access JWT — 1 час.
POST /auth/refresh автоматически обновляет JWT без закрытия страницы и форм. Параллельные запросы используют одну попытку обновления. Если продлить вход нельзя, страница остаётся открытой; повторный вход доступен в диалоге без потери формы.
POST /auth/logout отзывает refresh-сессию в БД и удаляет cookie. Уже выданный JWT действует до собственного срока истечения. У refresh-сессии абсолютный срок: обновление JWT не продлевает 7-дневный срок входа.

userservice возвращает в UserSettingsResponse дополнительный boolean telegramVerified:
сайт отличает подтверждённую привязку от старого вручную записанного Telegram ID.
Привязка делается только через POST /auth/telegram/code и команду в боте.
Ни один внутренний секрет сервиса на сайт не передаётся.

## Сборка и проверки

```sh
npm test
npm run build
npm run preview
```

Тесты проверяют HTTP-контракты, передачу JWT, обработку ошибок/401,
срок сессии, сохранение маршрута и отображение местного времени.
Backend: из корня проекта ./mvnw.cmd -pl userservice,tripservice -am test.

## Размещение

Результат npm run build находится в dist. В production сервер должен раздавать
этот каталог и проксировать /api/* к соответствующим Java-сервисам, сохраняя
Authorization. Пример — nginx.conf.example. Настройте HTTPS и реальные upstream-адреса.
Конфигурация Vite proxy действует только для dev/preview, она не встраивается в dist.
Имя бота VITE_TELEGRAM_BOT_USERNAME задаётся перед сборкой.
Не публикуйте dev/preview-сервер как production-сервер.

Заголовочный шрифт Golos Text загружается из Google Fonts; при недоступности сети
интерфейс использует системный шрифт. Других внешних ресурсов оформление не требует.

## Дополнительные настройки backend

- JWT_TTL_SECONDS в userservice: по умолчанию 3600.
- WEB_SESSION_TTL_SECONDS: по умолчанию 604800 (7 дней).
- WEB_SESSION_SECURE=true в production с HTTPS; локально false.
- USER_SERVICE_URL в tripservice: по умолчанию http://localhost:8082.
- Сессионная cookie: HttpOnly, SameSite=Strict, Path=/api/users/auth.
  Прокси должен сохранять Cookie и Set-Cookie. Для cookie-операций сайт передаёт
  X-TravelApp-Client: web, refresh/logout не принимают запросы без этого заголовка.
- Новые пароли: минимум 10 символов, строчная/прописная буква, цифра, спецсимвол;
  максимум 72 байта UTF-8, очевидные распространённые варианты отклоняются.
  Уже существующие пароли продолжают работать при входе.
