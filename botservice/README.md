# Telegram-интерфейс TravelApp

Тонкий клиент сервисов через Kafka: бот разбирает команды и оформляет ответы. Вход и привязка
Telegram выполняются userservice; маршруты и роли — tripservice; расходы,
распределение и долги — expensesservice. Бот не подключается к БД и не подписывает JWT.
Работа с аккаунтами доступна в личном чате.

## Запуск

Нужна Java 17+. Создайте бота через @BotFather.
В userservice и botservice задайте одинаковый случайный BOT_SERVICE_SECRET
(минимум 32 байта). Его нельзя передавать пользователям.

Переменные botservice:

| Переменная | Значение |
| --- | --- |
| BOT_ENABLED | true для запуска polling; по умолчанию false |
| TELEGRAM_BOT_TOKEN | Токен от @BotFather |
| BOT_SERVICE_SECRET | Общий секрет с userservice |
| BOT_OFFSET_FILE | ./bot-state/offset.txt |

Сначала запустите userservice, tripservice, expensesservice с их настройками БД
и одинаковым JWT_SECRET. Botservice JWT_SECRET не нужен.
Затем из корня проекта:

```powershell
.\mvnw.cmd -pl botservice,userservice -am install -DskipTests
$env:BOT_ENABLED = 'true'
# TELEGRAM_BOT_TOKEN и BOT_SERVICE_SECRET передайте через окружение.
.\mvnw.cmd -pl botservice spring-boot:run
```

Бот использует [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates)
с long polling, HTTP-сервер и webhook не требуются. Для одного токена запускайте
один polling-процесс. Notificationservice использует этот же токен только для отправки
напоминаний и не запускает polling. Существующий webhook для
токена нужно отключить через Telegram deleteWebhook перед включением polling.
Курсор обновлений сохраняется в BOT_OFFSET_FILE: сохраняйте этот файл при перезапуске.
Команды записи автоматически не повторяются при ошибках отправки ответа.
Полной гарантии exactly-once между Telegram и REST-сервисами нет.

## Начало работы и аккаунт сайта

- /start создаёт аккаунт по подтверждённому Telegram ID или входит в уже привязанный.
- /id показывает внутренний userId: сообщите его владельцу для добавления в поездку.
- /help показывает все команды и аргументы.

Чтобы подключить существующий аккаунт, сначала получите одноразовый код через
POST /auth/telegram/code на userservice с JWT этого аккаунта. В боте отправьте
/link код или /start код. Код действует 5 минут и используется один раз.
Пароль и JWT отправлять в чат не нужно. Непривязанный аккаунт не создаётся при /link.

Если /start уже создал отдельный аккаунт, автоматического объединения поездок нет.
Для переключения сначала сохраните другой способ входа в старый аккаунт,
затем /link отключить ДА и /link код_нужного_аккаунта.
Без другого способа входа или действующего кода отключение Telegram лишает доступа
к прежнему аккаунту. Удаление аккаунта и отключение Telegram требуют аргумент ДА.

Старое ручное POST /users/{id}/settings/telegram закрыто. PUT настроек больше
не меняет telegramId. Старые вручную записанные telegramId не дают права входа:
привязку нужно подтвердить кодом. Признак telegramVerified хранится в userservice.
Внутренние POST /internal/auth/telegram и /internal/auth/telegram/link доступны
только с X-Bot-Secret; они выдают JWT, который бот передаёт обычным REST-сервисам.
Внешний доступ к сервисам должен идти через HTTPS.

## Команды

Аргументы разделяются символом |. Символ | внутри значения не поддерживается.
Суммы можно вводить с точкой или запятой. Время участка: ДД.ММ.ГГГГ ЧЧ:ММ
(например, 01.11.2026 10:00). Прежний ISO-формат также принимается.

```text
/me
/profile имя | Europe/Moscow | RUB | 1000
/currency EUR
/balance 2000
/link
/link код
/link отключить ДА
/account_delete ДА

/trips
/trip 1
/trip_create Отпуск | Летим через Стамбул | Лондон
/leg_add 1 | Москва | Стамбул | 01.11.2026 10:00 | Europe/Moscow | 01.11.2026 14:00 | Europe/Istanbul
/leg_add 1 | Стамбул | Лондон | 01.11.2026 16:00 | Europe/Istanbul | 01.11.2026 17:00 | Europe/London
/trip_update 1 | Новое название | Новое описание
/leg_remove 1 | 2
/trip_delete 1 | ДА
/members 1
/member_add 1 | 2 | MEMBER
/member_role 1 | 2 | READ_ONLY
/member_remove 1 | 2

/expenses 1
/my_expenses 1
/summary 1
/my_summary 1
/expense_add 1 | 1200 RUB | Ужин на всех
/expense_add 1 | 12000 RUB | Билеты | 1,2,3,4
/expense_delete 1 | 5
```

В /profile пустое необязательное поле задаётся как -.
/currency меняет валюту профиля, /balance — его существующее поле amount;
эти команды не конвертируют деньги. Для расходов валюта указывается отдельно.
Поездка создаётся с направлением без участков маршрута; их можно добавить позднее.
Номер участка маршрута начинается с 1. Последний участок тоже можно удалить:
направление поездки сохранится. Проверку прав и хронологии выполняет tripservice.

В /expense_add больше не нужно указывать плательщика и дату: сервис берёт пользователя
из JWT и сегодняшнюю дату. Часовой пояс даты задаётся в expensesservice переменной
EXPENSES_TIME_ZONE (по умолчанию Europe/Moscow).
Без списка ID сумма делится поровну на всех текущих участников, включая вас;
с последним полем | 1,2,3 — только между указанными участниками.
Дату в прошлом, другого плательщика и неравные доли можно задать через полный REST API.
Команды настроек, отдельные команды управления Telegram и ручное распределение долей
убраны из бота. Для привязки достаточно /start (автоматический вход) или /link код
(подключение существующего аккаунта).
Сводки сохраняют расчёты и разделение валют expensesservice.

Тесты: `./mvnw.cmd -pl botservice,userservice,tripservice,expensesservice -am test`.
Они не отправляют сообщения настоящему боту; используются заглушки Kafka-клиента, HTTP-заглушки Telegram и H2.

Общие Kafka и Redis: [запуск и настройки](../INFRASTRUCTURE.md).
